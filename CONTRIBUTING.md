# Contributing

Thanks for helping. Bug reports with logs are just as valuable as code: the [bug report template](.github/ISSUE_TEMPLATE/bug_report.md)
lists what to attach.

## Building

Needs Xcode Command Line Tools (`clang`, `swiftc`) and a .NET 8 SDK.

```bash
scripts/build.sh
```

`dist/` then contains the app as a DMG and a zip, the Homebrew tarball (`macaqueloader-<version>.tar.gz`), a filled-in
Homebrew formula (`macaqueloader.rb`) and `SHA256SUMS`. `DOTNET=/path/to/dotnet scripts/build.sh` uses a specific SDK.
The build downloads the pinned MelonLoader release once (into `.cache/`) to compile the plugin against it; no
third-party binaries are committed.

## Repository layout

| Path | What |
|---|---|
| `app/Sources/` | MacaqueLoader, the SwiftUI app: detection (`Engine.swift`), state machine (`AppModel.swift`), screens (`Views.swift`), illustrations (`Illustrations.swift`) |
| `app/snapshots/` | renders every screen from the real views, for review and the README |
| `installer/install.sh` | the engine: install, repair, uninstall (used by the app and the CLI) |
| `installer/payload/` | `launcher.sh` (starts Steam if needed, then the game), the Cpp2IL wrapper, the live log window |
| `bin/macaqueloader` | the CLI |
| `src/melonfix/` | native library injected into the game before MelonLoader (C) |
| `src/MacFixes/` | MelonLoader plugin (C#); `StandIns.g.cs` is generated by `gen_standins.py` |
| `packaging/` | Homebrew formula template, repository name |
| `docs/DESIGN.md` | every problem MelonLoader hits on macOS, and its fix |

## Debugging

- `macaqueloader debug on` (or **Debug logging** in the app) makes `melonfix.log` verbose and adds native and managed
  crash backtraces, and logs the IL of the plugin's struct-argument trampolines.
- `MELONFIX_AUTOTEST=modsmenu` opens Mod Helper's Mods menu automatically after the main menu loads.
- Harmony's own IL log: set `harmony_log_level = "IL"` in `UserData/Loader.cfg` (put it back to `"Warn"` after).

## Screenshots

```bash
SNAPSHOT_GAME_APP="/path/to/BloonsTD6.app" scripts/screenshots.sh --readme
```

Renders every screen in light and dark mode from the real SwiftUI views (no screen-recording permission needed) and
refreshes the images in `docs/readme/`. Without `SNAPSHOT_GAME_APP` a neutral placeholder replaces the game icon.

## Before opening a pull request

- `scripts/build.sh` succeeds.
- Shell scripts pass `shellcheck -S warning` (CI runs it).
- If you changed what the app shows, refresh the screenshots.
- The app only handles situations most users can run into; please keep machine-specific workarounds out.

## Releasing

1. Bump `VERSION`, add a `CHANGELOG.md` entry, commit, then tag `v<version>` and push the tag. The `release` workflow
   builds everything and publishes a GitHub Release with the DMG, zip, Homebrew tarball, formula and checksums.
2. Copy `macaqueloader.rb` from the release into the tap repo
   ([dimslalom/homebrew-tap](https://github.com/dimslalom/homebrew-tap)) as `Formula/macaqueloader.rb`.

Forking? `scripts/set-repo.sh <owner>/<repo>` points every URL at your repository.
